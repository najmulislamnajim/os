অপারেটিং সিস্টেম
শেখার পূর্ণ পরিকল্পনা

কম্পিউটার হার্ডওয়্যার আর আপনার প্রোগ্রামের মাঝে যে জাদু ঘটে — সেটাই OS। এই রোডম্যাপে theory ও hands-on দুটো সমান্তরালে, C-ভিত্তিক প্রজেক্ট সহ, শূন্য থেকে নিজের kernel বানানো পর্যন্ত।

০০

কেন OS শিখবেন, কীভাবে

why-and-how

সীমিত হার্ডওয়্যার (এক CPU, কিছু RAM) দিয়ে অনেকগুলো প্রোগ্রাম একসাথে কীভাবে চালানো যায়, নিরাপদে ও দক্ষভাবে?

🎯 কেন এটা সবচেয়ে গুরুত্বপূর্ণ CS বিষয় OS শেখা মানে শুধু একটা বিষয় শেখা নয় — এটা বাকি সবকিছুর নিচের স্তর বোঝা। কেন আপনার প্রোগ্রাম ধীর? কেন memory leak হয়? deadlock কী? কেন multithreading কঠিন? database কেন এভাবে ডিজাইন করা? — সব উত্তর OS-এ। সিস্টেম ডিজাইন ইন্টারভিউ, পারফরম্যান্স টিউনিং, ব্যাকএন্ড আর্কিটেকচার — সবকিছুর ভিত্তি এটাই।

দুটো দিক, একসাথে চালাবো

OS শেখার দুটো দিক আছে, আর ভালো শেখার জন্য দুটোই সমান্তরালে চালানো দরকার — একটা পড়লে অন্যটা হাতে করা:

দিককী শেখায়কীভাবে
Theory / Conceptprocess, scheduling, virtual memory, concurrency, file system — কীভাবে কাজ করেপড়া, ডায়াগ্রাম, ভিডিও
Hands-on / Systemssystem call, C দিয়ে OS প্রোগ্রামিং, নিজে ছোট OS বানানোকোড লেখা, প্রজেক্ট, xv6
💡 আমার সুপারিশকৃত পদ্ধতি প্রতিটা ধারণা পড়ার সাথে সাথে সেটা C-তে বাস্তবায়ন করুন। যেমন — scheduling পড়ার পর একটা ছোট scheduler simulate করুন; virtual memory পড়ার পর mmap নিয়ে খেলুন। "পড়লাম কিন্তু বানালাম না" — OS-এ এই ফাঁদ সবচেয়ে বড়। যা বানাতে পারবেন না, তা বুঝেছেন বলে ধরবেন না।
📚 দুটো কিংবদন্তি রিসোর্স (শুরুতেই জেনে রাখুন) OSTEP (Operating Systems: Three Easy Pieces) — বিনামূল্যে অনলাইন বই, সবচেয়ে সহজ ও সেরা শুরুর জায়গা। তিন ভাগ: Virtualization, Concurrency, Persistence।
xv6 — MIT-র একটা ছোট শিক্ষামূলক OS (C-তে, ~৯০০০ লাইন), যেটা পড়ে ও পরিবর্তন করে আসল kernel কীভাবে কাজ করে বোঝা যায়। MIT 6.1810 কোর্সের ভিত্তি।

সম্পূর্ণ মানচিত্র

the-full-map

পুরো যাত্রাটা ৬টা মডিউলে ভাগ করেছি। প্রতিটা আগেরটার উপর দাঁড়িয়ে। নিচে এক নজরে পুরো পথ:

🧭 তিন স্তম্ভ মনে রাখুন পুরো OS আসলে তিনটা বড় ধারণার চারপাশে ঘোরে: Virtualization (একটা CPU/RAM-কে অনেকভাবে দেখানো — process ও virtual memory), Concurrency (একসাথে অনেক কাজ সামলানো), Persistence (বিদ্যুৎ গেলেও ডেটা রাখা — file system)। প্রতিটা মডিউল এই কোনো না কোনো স্তম্ভের অংশ।
০২

মডিউল ১ — ভিত্তি

foundations

OS আসলে কী, কেন দরকার, আর হার্ডওয়্যারের সাথে কীভাবে কথা বলে। এই মডিউল ছাড়া বাকিগুলো ধোঁয়াশা থাকবে।

১

OS-এর ভূমিকা ও গঠন

১-২ সপ্তাহ

OS কী কাজ করে (resource manager + hardware abstraction), kernel vs user space, monolithic vs microkernel, boot process।

kernel/user modesystem callinterruptboot processOS-এর ইতিহাস

যা যা শিখবেন

  • Kernel vs User space: কেন দুটো আলাদা "মোড", আর কেন এটাই নিরাপত্তার ভিত্তি
  • System call: আপনার প্রোগ্রাম কীভাবে kernel-এর কাছে সাহায্য চায় (read, write, fork) — user থেকে kernel-এ ঢোকার একমাত্র বৈধ দরজা
  • Interrupt ও trap: হার্ডওয়্যার কীভাবে CPU-র মনোযোগ কাড়ে
  • OS-এর স্থাপত্য: monolithic (Linux) vs microkernel (Minix) — সুবিধা-অসুবিধা
🛠 হাতে-কলমে প্রজেক্ট strace দিয়ে গোয়েন্দাগিরি: strace ls চালিয়ে দেখুন একটা সাধারণ কমান্ড কতগুলো system call করে। তারপর C-তে সরাসরি system call ব্যবহার করে (glibc ছাড়া, syscall() দিয়ে) একটা ছোট প্রোগ্রাম লিখুন যা "Hello" প্রিন্ট করে — বুঝবেন printf-এর নিচে কী ঘটে।

০৩

মডিউল ২ — Process ও Scheduling

virtualizing-cpu

Virtualization-এর প্রথম অংশ: একটা CPU-কে কীভাবে অনেকগুলো প্রোগ্রামের মধ্যে ভাগ করা হয়, যাতে প্রত্যেকে মনে করে সে একাই CPU পাচ্ছে।

২

Process, Thread ও CPU Scheduling

২-৩ সপ্তাহ

Process কী, কীভাবে তৈরি হয় (fork/exec), state machine, context switch, আর কোন process কখন CPU পাবে তার অ্যালগরিদম।

process statefork/exec/waitcontext switchPCBFCFS/RR/MLFQIPC

যা যা শিখবেন

  • Process lifecycle: new → ready → running → waiting → terminated, আর PCB (Process Control Block)-এ কী থাকে
  • fork/exec/wait: UNIX-এর process তৈরির মডেল — কেন fork দুবার return করে, কেন exec আলাদা
  • Context switch: এক process থেকে আরেকটায় যেতে কী সংরক্ষণ করতে হয়, আর কেন এটা ব্যয়বহুল
  • Scheduling অ্যালগরিদম: FCFS, SJF, Round Robin, Priority, আর বাস্তব MLFQ (Multi-Level Feedback Queue)
  • IPC: pipe, shared memory, message passing — process-রা কীভাবে কথা বলে
🛠 হাতে-কলমে প্রজেক্ট নিজের shell বানান: C-তে একটা ছোট shell লিখুন যা fork + exec + wait দিয়ে কমান্ড চালায়, pipe (|) সামলায়, আর background job (&) সাপোর্ট করে। এটা একটা ক্লাসিক প্রজেক্ট — process নিয়ে সব ধারণা একসাথে পাকা হয়ে যাবে।

বোনাস: একটা scheduler simulator লিখুন যা বিভিন্ন অ্যালগরিদমের average waiting time তুলনা করে।

০৪

মডিউল ৩ — Memory ও Virtual Memory

virtualizing-memory

Virtualization-এর দ্বিতীয় অংশ, আর OS-এর সবচেয়ে সুন্দর ধারণা: প্রতিটা process মনে করে তার কাছে পুরো RAM আছে, অথচ বাস্তবে সবাই ভাগ করে নিচ্ছে।

৩

Address Space, Paging ও TLB

২-৩ সপ্তাহ

Virtual address কীভাবে physical address-এ অনুবাদ হয়, page table, TLB, page fault, আর swap।

virtual addresspagingpage tableTLBpage faultswapsegmentation

যা যা শিখবেন

  • কেন virtual memory: নিরাপত্তা (এক process আরেকটার memory ছুঁতে পারে না), সরলতা (প্রতিটা program মনে করে ০ থেকে শুরু), দক্ষতা
  • Paging: memory-কে fixed-size page-এ ভাগ, page table দিয়ে virtual → physical অনুবাদ
  • TLB: প্রতিটা অ্যাক্সেসে page table দেখা ধীর, তাই একটা hardware cache — TLB miss কেন performance-এ বড় প্রভাব ফেলে
  • Multi-level page table: পুরো page table RAM-এ রাখা অবাস্তব, তাই স্তরে স্তরে
  • Page replacement: RAM ভরে গেলে কোন page swap করবে — LRU, Clock অ্যালগরিদম
🛠 হাতে-কলমে প্রজেক্ট malloc নিজে লিখুন: একটা সরল memory allocator বানান (my_malloc/my_free) — free list, splitting, coalescing সহ। বুঝবেন heap কীভাবে কাজ করে, fragmentation কী।

আরও: mmap দিয়ে একটা ফাইলকে memory-তে map করে দেখুন; page fault handler নিয়ে খেলুন (SIGSEGV ধরে)।

মডিউল ৪ — Concurrency

concurrency

OSTEP-এর দ্বিতীয় স্তম্ভ, আর সবচেয়ে কঠিন অংশ। একসাথে অনেক thread চললে জিনিস কীভাবে ভাঙে, আর কীভাবে ঠিক করা যায়।

৪

Thread, Lock, Deadlock ও Synchronization

৩ সপ্তাহ

Race condition, mutex, semaphore, condition variable, deadlock — আর কেন concurrency এত কঠিন।

race conditionmutexsemaphorecondition variabledeadlockproducer-consumer

যা যা শিখবেন

  • Race condition: কেন counter++ দুটো thread-এ চললে ভুল হয় (এটা আসলে তিনটা অপারেশন)
  • Mutex ও lock: critical section রক্ষা করা, আর lock-এর খরচ
  • Semaphore ও condition variable: শুধু রক্ষা নয়, thread-দের সমন্বয় করা
  • Deadlock: চারটা শর্ত (mutual exclusion, hold-and-wait, no preemption, circular wait) আর কীভাবে ভাঙা যায়
  • ক্লাসিক সমস্যা: producer-consumer, readers-writers, dining philosophers
🛠 হাতে-কলমে প্রজেক্ট Thread-safe কিছু বানান: pthread দিয়ে একটা thread-safe queue, বা একটা bounded buffer (producer-consumer) implement করুন mutex + condition variable দিয়ে। ইচ্ছাকৃতভাবে lock ছাড়া চালিয়ে race condition দেখুন, তারপর ঠিক করুন।

চ্যালেঞ্জ: dining philosophers সমাধান করুন deadlock ছাড়া।
⚠️ এখানে ধীরে চলুন Concurrency-র বাগ ভয়ংকর কারণ সেগুলো অনির্দিষ্ট — কখনো হয়, কখনো হয় না। এই মডিউলে তাড়াহুড়ো করবেন না; প্রতিটা ধারণা কোডে দেখে নিশ্চিত হন। এটাই বাস্তব চাকরিতে সবচেয়ে বেশি কাজে লাগবে (multithreaded ব্যাকএন্ড, database)।

মডিউল ৫ — Storage ও File System

persistence

তৃতীয় স্তম্ভ: Persistence। বিদ্যুৎ চলে গেলেও ডেটা কীভাবে থাকে, আর disk-এর ধীরগতি কীভাবে সামলানো হয়।

৫

File System, Disk ও I/O

২-৩ সপ্তাহ

File কীভাবে disk-এ সংরক্ষিত হয়, inode, directory, journaling, আর I/O কীভাবে দ্রুত করা হয়।

inodedirectoryFAT/extjournalingdisk schedulingbuffer cacheRAID

যা যা শিখবেন

  • File system-এর গঠন: inode (metadata), data block, directory কীভাবে নাম থেকে inode-এ ম্যাপ করে
  • কীভাবে একটা ফাইল খোঁজা হয়: path থেকে block পর্যন্ত পুরো যাত্রা
  • Crash consistency: লেখার মাঝে বিদ্যুৎ গেলে কী হয়, journaling কীভাবে বাঁচায়
  • Disk scheduling: HDD-তে head movement কমানো (SCAN, C-SCAN), আর SSD কেন আলাদা
  • Buffer cache: কেন OS ডিস্ক ডেটা RAM-এ ক্যাশ করে
🛠 হাতে-কলমে প্রজেক্ট ছোট file system বানান: একটা ফাইলকে "ভার্চুয়াল ডিস্ক" ধরে তার উপর একটা সরল file system implement করুন — superblock, inode, data block সহ। create, read, write, ls সাপোর্ট করুন। এটা persistence-এর সব ধারণা একসাথে পাকা করবে।

সহজ শুরু: FUSE ব্যবহার করে একটা toy file system, যা userspace-এ চলে।

মডিউল ৬ — নিজের OS বানানো

build-your-own

সব ধারণা একসাথে জোড়া লাগানোর সময়। একটা আসল (ছোট) OS-এর কোড পড়ে, পরিবর্তন করে, আর নিজে কিছু বানিয়ে আপনি "বুঝেছি" থেকে "পারি"-তে যাবেন।

৬

xv6 ও Kernel Hacking

৪-৬ সপ্তাহ

MIT-র xv6 (একটা শিক্ষামূলক UNIX-সদৃশ OS) পড়া, বোঝা, আর তাতে নতুন feature যোগ করা।

xv6 sourcebootloadersyscall যোগscheduler বদলQEMUdebugging

যা যা করবেন

  • xv6 পড়া: ~৯০০০ লাইনের একটা সম্পূর্ণ OS — boot থেকে shell পর্যন্ত সব দেখা যায়
  • নতুন system call যোগ: নিজে একটা syscall লিখে kernel-এ ঢোকানো
  • Scheduler পরিবর্তন: xv6-র সরল scheduler-কে MLFQ বা lottery scheduling-এ বদলানো
  • QEMU-তে চালানো ও GDB দিয়ে debug করা: আসল kernel debugging-এর অভিজ্ঞতা
🛠 চূড়ান্ত পথ — দুটো বিকল্প পথ ক (সুপারিশকৃত): MIT 6.1810-র সব lab করুন — এগুলো xv6-এর উপর ভিত্তি করে, ধাপে ধাপে আপনাকে kernel hacking শেখায়। বিনামূল্যে, বিশ্বমানের।

পথ খ (উচ্চাভিলাষী): "OSDev" উইকি অনুসরণ করে একদম শূন্য থেকে নিজের OS লিখুন — bootloader থেকে। কঠিন, কিন্তু অসাধারণ শিক্ষা। শুধু যথেষ্ট সময় থাকলে।
📚 রিসোর্স MIT 6.1810 (পুরো কোর্স, বিনামূল্যে) · xv6 book (MIT থেকে বিনামূল্যে PDF) · OSDev wiki · "Writing an OS in Rust" (আধুনিক বিকল্প)

📅 আদর্শ সাপ্তাহিক ছন্দ ৪০% পড়া (OSTEP অধ্যায় + লেকচার) → ৪০% কোড (সেই সপ্তাহের প্রজেক্ট) → ২০% রিভিশন (আগের ধারণা ঝালাই, ছোট প্রশ্নের উত্তর)। মূলনীতি: একটা মডিউল "শেষ" ততক্ষণ নয়, যতক্ষণ না তার প্রজেক্টটা কাজ করছে।

অগ্রগতি ট্র্যাক করুন

  • মডিউল ১: strace বিশ্লেষণ + raw syscall প্রোগ্রাম কাজ করছে
  • মডিউল ২: নিজের shell (pipe + background job সহ) কাজ করছে
  • মডিউল ৩: my_malloc (coalescing সহ) কাজ করছে
  • মডিউল ৪: thread-safe producer-consumer + dining philosophers deadlock-মুক্ত
  • মডিউল ৫: toy file system (create/read/write/ls) কাজ করছে
  • মডিউল ৬: xv6-তে নতুন syscall + পরিবর্তিত scheduler কাজ করছে
⚠️ সবচেয়ে বড় দুটো ফাঁদ ১. শুধু পড়া, না বানানো: OS ভিডিও দেখে "বুঝেছি" মনে হয়, কিন্তু কোড না লিখলে সেটা মুছে যায়। প্রতিটা মডিউলের প্রজেক্ট বাধ্যতামূলক ধরুন।
২. সব একসাথে শেখার চেষ্টা: OS বিশাল। ক্রম মেনে একটা একটা করে যান — Concurrency বোঝার আগে Process না বুঝলে হোঁচট খাবেন।
